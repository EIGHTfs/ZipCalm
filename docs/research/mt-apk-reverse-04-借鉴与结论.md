## 一、借鉴清单

| MT 的做法 | 借鉴 | 理由 |
|---|---|---|
| 用 `sevenzipjbinding`（7-Zip JBinding）覆盖全格式 | ❌ 不借鉴 | 需 native 绑定，与「零依赖优先」冲突。我们走「Node 内置 + 可选外部二进制」 |
| **常用密码自动尝试 + 记住最近成功密码**【资源】 | ✅ **强烈建议** | 直接消灭「忘记密码 = 数据不可读」这个不可逆风险 |
| **压缩包测试期间的变化检测**【资源】 | ✅ 借鉴 | 与我们的 P-06（校验通过到删除之间源文件可能变）同类，印证「一致性要单独校验」 |
| 不解压浏览压缩包内容【资源】 | ✅ 后续可加 | 用户能先看内容再决定是否解压 |
| 分卷压缩【资源】 | ⚠️ 可选 | 大文件分发有用，但增加复杂度；非当前需求 |
| 压缩级别 + 「大小优先」策略【资源】 | ✅ 部分借鉴 | 我们已有 `levelRange` / `defaultLevel`，可补「策略」语义 |
| **SMB 上不直接压，引导用户先复制到本地**【资源】 | ✅ **反向印证** | MT 是"产品上绕开"，ZipCalm 是"让 NAS 自己压"，同向且更进一步 |
| 混淆 + native 保护核心逻辑 | — | 商业软件做法，开源项目不需要 |

### 最重要的一条：SMB 策略的印证价值

MT 有完整 SMB 读写栈（SMBJ），**技术上完全可以远程读文件**，但产品上选择：

```
压缩级别 Q%s 当前目录权限不足，请将压缩文件复制到内部存储后再操作
%s 当前目录权限不足，无法直接解压，可先解压到其它文件夹再复制过来
```

**这说明「手机端压缩 NAS 文件」的真正痛点不是"做不到"，而是"数据要过一遍手机"** —— 几十 GB 经 WiFi 往返，慢且费流量。

**ZipCalm 的价值主张因此更清晰**：把压缩任务发给 NAS，数据不离开磁盘。这不是"补 MT 的缺陷"，而是**换了一条根本不同的路径**。

> ⚠️ **同时修正一个前提**：我们此前写「MT 原生压缩 SMB 文件时按钮是灰的」（`docs/09` §11.2 旧文），从证据看**不准确** —— 实际是**点击后弹权限提示**，不是禁用态。该说法已从文档中移除，若将来要引用需真机确认。

## 二、对 ZipCalm 待办功能（`docs/18`）的直接影响

| 功能 | 逆向带来的具体输入 |
|---|---|
| **① 7z / rar** | MT 证明「全格式 = native 绑定」，印证我们「调 `7z` 二进制」的方向是对的；纯 JS 库做不到全格式覆盖。同时确认 rar 只读是行业常态（MT 也没有自由 rar 写入实现） |
| **② 压缩包密码** | **必须加「常用密码自动尝试 + 记住最近成功密码」** —— 已写入 `docs/18`。这是本册最有价值的产出 |
| **③ 硬链接预检提示** | 无直接输入（MT 不涉及硬链接去重），但「测试期间变化检测」的思路可复用到预检的一致性校验 |

## 三、插件路线：最终判定（三册证据汇总）

| 阻断点 | 证据来源 | 结论 |
|---|---|---|
| 无文件管理器 / 压缩扩展点 | 第 3 册 §四（84 个 API 类，扩展点仅 editor / translation / regex） | ❌ 硬阻断 |
| `PluginContext` 无用户文件访问能力 | 第 3 册 §四（SDK v3 接口全方法核对，仅 `getFilesDir()` 自己的目录） | ❌ 硬阻断 |
| 宿主 API 与官方 v3 文档一致 | 第 3 册（`bin.mt.plugin.api` 原样打进 dex，无隐藏能力） | 排除「文档没写但实际有」的可能 |

**判定：MT 插件路线彻底不可行。** 这不是「等 API 升级」，而是插件沙箱模型本身不提供文件侧能力 —— 即使将来开放文件菜单扩展点，只要 `PluginContext` 不给文件访问，仍然做不了。

**M9 维持 PWA 方向。**

## 五、结论

1. **压缩实现可学的是「库选型 + 功能设计」，不是代码** —— MT 用 7-Zip JBinding + zstd-jni，业务层混淆 + native 保护
2. **最值得抄的是「常用密码自动尝试」** —— 直接消灭「忘记密码」这个不可逆风险
3. **SMB 策略反向印证了 ZipCalm 的价值** —— MT 选择"让用户先复制"，我们选择"让 NAS 自己压"
4. **MT 插件路线彻底不可行** —— 双重阻断（无扩展点 + 无文件访问），已从宿主侧独立复核
5. **M9 继续走 PWA**
