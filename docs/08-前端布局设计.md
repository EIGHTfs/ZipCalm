# 08 前端布局设计

> 定位：网盘式布局骨架、桌面与触屏两套交互、右键菜单与拖拽。
> 本文结论已与 `web/src/` 实现核对（2026-10-24）。

## 一、整体布局：侧边栏 + 主区 + 底部状态栏

Web 文件管理器的经典三件套：

| 区域 | 放什么 |
|---|---|
| **左侧栏** | 导航（文件浏览 / 压缩任务 / 硬链接去重 / 性能看板 / 设置）+ 存储位置列表（带容量条） |
| **顶部工具栏** | 面包屑（含当前存储位置）+ 搜索 + 视图切换 + 用户态 |
| **主内容区** | 文件列表（当前目录）、多选复选框、右键上下文菜单 |
| **底部状态栏** | 运行状态（活跃/排队任务数、SSE 连接状态、当前任务） |

## 二、文件浏览区：两种视图

| 模式 | 适用 | 特点 |
|---|---|---|
| **列表视图**（`VIEW_MODE.LIST`） | 看大小/时间、批量操作 | 紧凑表格、信息密度高、复选框列直观 |
| **网格视图**（`VIEW_MODE.GRID`） | 缩略图、触屏 | 卡片式、点击区域大 |

**默认策略**：桌面默认**列表**（批量压缩时多选与排序更高效）；**触屏自动切网格**（`isTouch && viewMode === LIST → GRID`）。

## 三、压缩交互：不离开当前目录

参考桌面压缩工具的体验，压缩流程分四层，核心是**用户始终停留在文件浏览界面**：

**入口层**：选中文件 → 工具栏「压缩」按钮变可用（未选中时禁用并说明「先选中文件」）；或右键菜单第一项。

**设置层**：点击「压缩」→ 右侧抽屉滑出，内容：格式（zip / tar.gz / tar.zst / tar）、模式（单独 / 打包）、保留原文件、黑名单开关。抽屉顶部显示「已选 N 项 · 产物将保存到「<当前存储位置>」的 <路径>」，底部「开始压缩」。

**执行层**：抽屉收起 → 底部任务条出现，显示任务名 + 进度 + 取消按钮；点击可展开完整任务列表。

**完成层**：任务完成显示「节省了 X MB（原 Y MB → 压缩后 Z MB）」；若原文件已删，目录里只剩压缩包。

## 五、右键菜单比顶部工具栏更重要

选中文件后最高频的操作是「压缩」，它必须出现在**右键菜单第一项**，而不是让用户跑到顶部找按钮。

三套菜单（文件 / 目录 / 空白）按使用频率排序：

- **文件**：压缩、解压（若是压缩包）、重命名、移动、复制路径、删除
- **目录**：压缩、进入、重命名、移动、复制路径、删除
- **空白**：新建文件夹、刷新、全选、粘贴

压缩设置面板做成**弹出式侧边抽屉**，确认后收起，不打断浏览上下文。

## 六、两套 UI 的决策

采用两套 UI：**APK 等网页端完全开发完再开始**。各自专注一个交互模型，不必为不同平台、不同终端尺寸追求「显示效果一致」；网页端先按鼠标操作开发，触屏只做最低兼容。

**理由**：响应式适配所有尺寸看似省事，实际每个断点都要单独调、每个设备都要测，最后往往每个体验都不极致。

## 七、网页端：用好鼠标

**1. 右键上下文菜单** —— 文件管理器最核心的交互（见 §五）。

**2. 悬停高亮** —— 悬停文件行显示完整信息；悬停按钮显示 tooltip；拖拽时高亮目标目录。

**3. 复选框列** —— 每行左侧复选框，可直接点多选，也可点文件名打开。比「按住 Ctrl 点击」直观。

**4. 键盘快捷键** —— `Ctrl+A` 全选、`Delete` 删除、`F2` 重命名、`Enter` 打开、`Esc` 退出选择、上下箭头导航。

**5. 拖拽** —— 拖文件到目录树 = 移动；拖文件到压缩按钮 = 直接压缩；拖出浏览器 = 下载。

**6. 侧边栏常驻** —— 桌面屏幕宽，侧边栏不收起。

**7. 两栏布局** —— 左：导航 + 存储位置；右：文件列表；底部任务条。

## 八、触屏兼容：最低可点，不独立设计

**核心：交互模型不变，只是「右键」变「长按」、「悬停」变「常显」。**

- **长按 = 右键的等效**：长按文件弹出上下文菜单（与右键菜单同一套实现）
- **触摸目标够大**：按钮 ≥ 40×40 px，行高 ≥ 44 px
- **不依赖悬停**：只在 `:hover` 显示的操作，触屏上等于不存在
- **禁双击缩放干扰**：列表区域 `touch-action: manipulation`
- **禁长按选中文字**：文件项 `user-select: none` + `-webkit-touch-callout: none`

### 触屏交互要点

1. **选择模式是「长按进入」，不是「点击选中」**：点击 = 打开/进入；长按 = 进入选择模式；选择模式下点击空白退出
2. **多选是「全屏选择态」**：进入选择模式后顶部显示「已选 X 项」+ 全选按钮，文件行/卡片高亮（复选框在触屏上太小）
3. **底部操作栏不超过 5 个按钮**，超出用「更多」折叠
4. **压缩设置用抽屉而非居中模态**：触屏上从底部/右侧滑出更好操作
5. **任务进度常驻可见**：底部浮动条 + 点击展开
6. **滑动操作是加分项**：左滑删除在触屏上容易误触，删除这类危险操作不用滑动触发

> **实现现状**：触屏底部操作栏已按需求隐藏（`SHOW_TOUCH_BOTTOM_BAR = false`，代码保留待重新设计），当前由工具栏按钮 + 长按菜单覆盖。见 [17-设计与实现差异记录](17-设计与实现差异记录.md) E-1。

```
web/src/
├── pages/          FilesPage（含列表/网格/右键/键盘/选择）· TasksPage · MetricsPage · SettingsPage · HardlinkPage · LoginPage
├── components/
│   ├── layout/     TopBar · Sidebar · MainArea · DirectoryTree · BottomTaskBar
│   ├── compress/   CompressDrawer · ExtractDialog
│   ├── task/       TaskProgress · TaskDrawer
│   ├── metrics/    TrendChart
│   └── common/     ContextMenu · PromptDialog · Icon
├── stores/         ui · tasks · metrics · auth
├── api/            各资源封装（拦截器统一解信封）
└── styles/         base.css · layout.css
```

**列表与网格视图都在 `FilesPage.vue` 内实现**（未拆成独立组件）—— 两者共享同一份选中态、右键菜单与键盘逻辑，拆开会让状态同步成本高于复用收益。
