## 三、决策记录：6 个开放问题

| # | 开放问题 | 决策 | 理由 |
|---|---|---|---|
| 1 | `/fs/move` 同步还是异步任务 | **维持 v1 同步**（≤200 项，跨分区返回 `CROSS_DEVICE_UNSUPPORTED`） | 单用户 NAS 场景下移动大目录非常规操作；改成异步需要新增任务类型与状态分支，会显著抬升 M0 契约复杂度。M8 若实测确有需求，按「新增任务类型」扩展，属非破坏性变更 |
| 2 | 确认删除是否加 sha256 摘要比对 | **维持 `expectedFiles` / `expectedBytes` 回传比对**，不加 sha256 | INV-01（`test()` 全绿）+ INV-02（条目集合精确比对）已覆盖数据安全；sha256 需完整重读产物，大包代价高、收益边际。M5 验收若发现集合比对不足再补 |
| 3 | 任务历史保留策略 / 是否暴露清理端点 | **v1 保持 200 条**，清理端点推迟到 M8 | 200 条对单用户足够；「清理历史 / 清空回收站」属运维便利，不阻塞主链路，放打磨期实现更合适 |
| 4 | `.part` 在 `interrupted` 后的处置 | **维持保留**；新增配置字段 `storage.partRetentionDays`（默认 7），清理逻辑 M8 实现 | 保留是「可重试」的前提（INV-10）；但长期占用磁盘需兜底。M0 只冻结字段与语义，不实现清理 |
| 5 | `INTERRUPTED` / `ABORTED` 是否暴露到 HTTP 层 | **维持仅出现在任务内 `error.code`** | 二者是任务生命周期状态（已由 `status` 表达），不是请求失败；上 HTTP 层会与「4xx 客户端可修正 / 5xx 可重试」的语义冲突 |
| 6 | `docs/M0` 是否登记进 README 文档索引 | **补登** | 新目录不被索引即不可发现；已在主 README 的文档索引表补一行 |

## 四、冻结后的规则

1. 本目录四份文档为 **v1 契约**：实现必须严格遵循；契约与实现不一致时，以契约为准并修正实现。
2. 破坏性变更（端点语义、字段含义、状态机、错误码语义）→ 加 `/api/v2/`；非破坏性变更（新增端点、新增错误码、新增可选字段）→ 更新本目录文档并在提交信息中注明。
3. 任何「不变量」被破坏视为 **P0 缺陷**，禁止进入下一里程碑（`docs/11` §二「不通过不进下一阶段」）。
