# M0 契约冻结 · 压缩格式插件契约（v1）

> 文档状态：**M0 冻结候选**（依据 `docs/11-开发里程碑与验收标准.md` 第三节 M0 交付物、`docs/03` 插件化架构）
> 契约版本：`format-plugin/v1`。冻结后新增格式**只加包 + 注册**，不允许改主逻辑（M4 验收）。
> 关联契约：[API规范.md](API规范.md) · [数据模型.md](数据模型.md) · [不变量清单.md](不变量清单.md)
> 一句话边界：**格式包只负责「怎么压」，不负责「压完删不删、任务排不排队、磁盘够不够」。**（docs/03 §二）

---

## 一、定位：谁是格式包，谁不是

| 能力 | 归属 | 说明 |
|---|---|---|
| 组装压缩包（读取源文件 → 写出归档文件） | **格式包** | 唯一职责 |
| 列出归档内容（校验用） | **格式包** | `list()` |
| 完整性校验（CRC / 解压读通） | **格式包** | `test()` |
| 当前环境能否执行（如 zstd 二进制在不在） | **格式包** | `available()` |
| 预估压缩后大小（空间预检分母） | **格式包** | `estimate()` |
| 路径白名单 / 防穿越 | 总入口 | `http/middleware/pathGuard.js` + `core/fs/safePath.js` |
| 磁盘空间预检（≥ 2 倍） | 总入口 | `core/compress/preflight.js` |
| 任务排队 / 并发 / 串行 | 总入口 | `core/task/queue.js` |
| 黑名单命中与跳过 | 总入口 | `core/blacklist/matcher.js` |
| 产物命名与防覆盖 | 总入口 | `core/compress/orchestrator.js` |
| 校验 → 删除原文件 → 回收站 → 日志 | 总入口 | `core/compress/verify.js` + `deleter.js` |
| 进度聚合 / 落盘 / SSE 推送 | 总入口 | `core/task/progress.js` |
| 配置读取、日志落盘、鉴权 | 总入口 | 格式包**不得**自己读配置/写日志文件 |

放置位置：`server/plugins/formats/<id>/index.js`（每格式一个目录，**删目录即删格式**，docs/12 §二）。

## 二、契约对象总览

每个格式包 `module.exports`（或 ESM 默认导出）一个满足下列形状的对象：

| 成员 | 类型 | 必选 | 说明 |
|---|---|---|---|
| `id` | `string` | ✅ | 唯一标识，注册表主键；同时是 API 的 `format` 取值 |
| `name` | `string` | ✅ | UI 显示名（`ZIP` / `TAR` / `TAR.GZ` / `TAR.ZST`） |
| `ext` | `string` | ✅ | **主扩展名，含点**；复合扩展名整体一个字符串（`.tar.gz`） |
| `extAliases` | `string[]` | 可选 | 同格式的其他扩展名（如 `[".tgz"]`），注册表一并建索引 |
| `mime` | `string` | ✅ | 下载 `Content-Type` |
| `levelRange` | `[min, max]` | 可选 | 支持的压缩级别区间；缺省表示不支持 `level` |
| `defaultLevel` | `number` | 可选 | 未传 `level` 时使用 |
| `available()` | `() => Promise<boolean>` | ✅ | 环境自检 |
| `unavailableReason()` | `() => Promise<string\|null>` | 可选 | 置灰原因文案（UI 悬停提示用） |
| `estimate(inputBytes, options)` | `(number, EstimateOptions) => Promise<EstimateResult>` | ✅ | 预估产物大小 |
| `create(ctx)` | `(CreateContext) => Promise<CreateResult>` | ✅ | 执行压缩 |
| `extract(ctx)` | `(ExtractContext) => Promise<ExtractResult>` | ✅ | 执行解压（与 `create` 对称；v1 新增） |
| `list(archivePath, options)` | `(string, ListOptions) => Promise<ListResult>` | ✅ | 列出归档内容 |
| `test(archivePath, options)` | `(string, TestOptions) => Promise<TestResult>` | ✅ | 完整性校验 |

> 说明：`available()` 的**语义**是布尔判定（"能不能跑"）。以 `tarzst` 为例：Node ≥ 22.15 的内置 zstd 可用 **或** 系统 `zstd` 命令可执行 → `true`；两者都不可用 → `false`，并由 `unavailableReason()` 说明原因。`unavailableReason()` 是**可选扩展**，只影响 UI 文案，不影响判定。

## 三、方法签名与语义

### 3.1 `ext` / `extAliases` / `mime` / `id` / `name`（静态元数据）

- `ext` 必须**以 `.` 开头**、全小写、不得含 `/`。复合扩展名（`.tar.gz`、`.tar.zst`）必须是**一个整体**，不允许用 `.gz` 代理——注册表按"最长复合扩展名优先"匹配（对齐参考实现 `format-registry.ts:40-48`，避免 `.tar.gz` 被 `.gz` 抢走）。
- `mime` 必须是下载时可直接使用的类型，例如 `application/zip`、`application/x-tar`、`application/gzip`、`application/zstd`。
- `id` 与 `ext` 在**全局注册表内唯一**；重复注册 = 启动失败（见第五章）。
- 元数据必须是**同步可得**的常量，不允许在元数据上做 I/O（启动注册表不等待任何异步探测）。

### 3.2 `available(): Promise<boolean>`

- 语义：**当前运行环境能否真正执行该格式的压缩**。
- 判定要点：依赖的外部二进制是否可执行（`which`/`fs.access(X_OK)`，不要只看文件存在，对齐"工具自探测"要求）；WASM/原生模块能否 `import` 成功并完成一次最小自检。
- 允许缓存探测结果，**但缓存 TTL ≤ 60s**（用户现场装了 zstd，最多 1 分钟 UI 就该亮起来）。
- 失败不得抛异常：返回 `false` 即可（可选实现 `unavailableReason()` 说明原因）。
- 调用者：`GET /api/v1/formats`、`POST /api/v1/compress/preflight`、`POST /api/v1/compress/tasks`。
- 契约要求：`available()===false` 时，`create()` 必须直接抛 `FORMAT_UNAVAILABLE`，不得半途失败。

### 3.3 `estimate(inputBytes, options): Promise<EstimateResult>`

```js
// options
{
  mode: 'single' | 'bundle',      // 影响成包数量，不影响单包比率的计算方式
  level?: number,                 // 压缩级别
  sample?: { names: string[] }    // 可选：文件类型抽样（扩展名），用于提高精度
}

// 返回
{
  estimatedBytes: number,         // 该包预估产物体积（bytes）
  ratio: number,                  // estimatedBytes / inputBytes，[0, 1.2] 之外视为异常
  basis: 'heuristic' | 'sample' | 'fixed',  // 依据来源，便于前端注明"预估"
  confidence: 'low' | 'medium' | 'high'
}
```

- 用途：空间预检的分母（`requiredBytes`，见 INV-04）、压缩设置抽屉的"预估压缩后大小"。
- **必须是廉价估算**：允许基于扩展名启发式（已压缩格式 ratio ≈ 0.98~1.0，文本/代码 ≈ 0.3，未压缩图片 ≈ 0.4），**禁止为此真的压一遍**。
- 纯不压缩格式（如 `tar`）：`ratio` 必须接近 1，并按"每条目 ~512B 头 + 512B 对齐填充"计入开销。
- `estimate` 不得产生副作用（不建文件、不写盘）。
- 调用者错误处理：`estimate` 抛错 → 总入口降级为 `ratio = 1.0`、`confidence = 'low'`，**不阻断任务**（预检仍按 2 倍校验，因为 `requiredBytes = inputBytes × 2` 与估算无关）。

### 3.4 `create(ctx): Promise<CreateResult>`

```js
// ctx（由总入口构造，格式包只读）
{
  taskId: string,                       // 任务 UUID，仅用于日志/诊断
  format: string,                       // 格式 id
  mode: 'single' | 'bundle',
  sources: [                            // 已过白名单 + 已过滤黑名单之后的待压条目
    { absPath: string, name: string, kind: 'file' | 'dir', size: number }
  ],
  outputPath: string,                   // 最终产物路径（平台原生绝对路径，仅供进程内使用）
  tempPath: string,                     // 必须写入的临时路径 = outputPath + '.part'
  options: {
    level?: number,
    preserveRoot: boolean,              // bundle 模式是否保留源目录名作为包内顶层目录
    mtime?: number,                     // 可选：统一归档时间戳（可复现产物）
    signal: AbortSignal                 // 取消信号
  },
  onProgress(p): void                   // 进度回调，见下
}

// onProgress 载荷（文件级 + 字节级两层，docs/05 §一）
{ processedBytes, totalBytes, processedFiles, totalFiles, currentFile }

// 返回
{
  outputPath: string,     // 已写好的 tempPath（总入口负责 rename 成 outputPath）
  entries: number,        // 实际写入条目数
  entryPaths: string[],   // **实际进包条目的源绝对路径**（进程内使用、不进 API；语义见条款 10）
  bytesIn: number,        // 读入原始字节
  bytesOut: number,       // 写出归档字节
  durationMs: number
}
```

契约条款（每条都可测）：

1. **只写 `tempPath`**，禁止直接写 `outputPath`；把 `.part` 原子 `rename` 成最终产物是**总入口**的职责（崩溃/取消时不会留下"看起来正常"的半成品）。
2. **流式**：使用 `pipeline()` 式流式管道，内存占用与文件大小无关；禁止 `readFileSync` 整个大文件。
3. **进度事件驱动**：每进一个文件发一次文件级进度；字节级按 **≥100ms 节流**（或每 1MB）上报（对齐 `FflateZipAdapter` 的 100ms 节流）。禁止定时器采样。
4. **取消**：监听 `options.signal`；收到 abort 后停止写入、关闭流、删除 `tempPath`，并抛 `CANCELLED`（错误码 `ABORTED`，见第八章）。
5. **完成**：必须等待输出流 `close` 才算写完（对齐 docs/10 wfmanager 的经验：`await archive.finalize()` 之后还要等 output 的 `close`）。
6. **绝不删除/移动源文件**，绝不改动源目录（这是总入口的删除流程，见 INV-01）。
7. **绝不覆盖**已存在的 `tempPath`/`outputPath`：若二者已存在，直接抛 `TARGET_EXISTS`（正常流程下总入口已保证路径唯一）。
8. **错误必须带码**：抛出的错误对象至少含 `{ code, message }`（第八章枚举），不得抛裸 `Error('something failed')`。
9. `create()` 返回后，`tempPath` 必须**完整且可被 `test()` 校验通过**。
10. **必须返回 `entryPaths[]`**：**实际进包条目的源绝对路径**清单（进程内使用、**不进 API** —— 用绝对路径没问题，且与扫描快照同坐标系，零转换）。它是**删除集合的唯一可信来源**：删除阶段用它减去 `result.skipped[]` 得到命中的源条目，再映射成契约形状的 `delete.targets`（见数据模型 §9.5）。
    - **不得**用"全部源条目"当删除集合；**不得**用删除前重扫 `list()` 反推（大包成本高，且中央目录损坏时 list 结果不可信，而 `create` 刚成功过，它才是第一手事实）。
    - **更不得**用**包内路径**（`entryName`）反推源路径 —— 反推要处理 `preserveRoot`、不同父目录同名、公共祖先边界，任一处判断错就是**删错文件**。删除依据必须用第一手映射；打包器在收集条目时本就持有 `{absPath, entryName}` 对，直接返回 `absPath` 即可，**零额外成本**。
    - 缺失该字段的格式包视为**未满足 v1 契约**。

### 3.4.1 `extract(ctx): Promise<ExtractResult>`（v1 新增，与 `create` 对称）

```js
// ctx（由总入口构造，格式包只读）
{
  taskId: string,
  format: string,
  archivePath: string,        // 待解压归档（已过白名单）
  targetDir: string,          // 解压目标目录（总入口确保存在且在存储根内）
  options: {
    stripComponents?: number, // 剥掉前 N 层目录（默认 0）
    overwrite: boolean,       // 目标已存在同名文件时是否覆盖（默认 false）
    signal: AbortSignal
  },
  onProgress(p): void         // 与 create 同形状：{ processedBytes, totalBytes, processedFiles, totalFiles, currentFile }
}

// 返回
{ targetDir: string, entries: number, bytesOut: number, durationMs: number }
```

契约条款：
1. **只写 `targetDir` 之内**，并且必须防「归档内路径逃逸」——**zip-slip 是解压侧的头号安全风险**：条目名含 `../`、绝对路径、盘符或符号链接指向目标目录外 → **必须拒绝**（规范化后再次校验，与 `pathGuard` 同一套判定）。
2. **流式**解压，内存占用与归档大小无关。
3. **进度事件驱动**（文件级每进一个文件、字节级 ≥100ms 节流），与 `create` 一致。
4. **取消**：监听 `options.signal`；abort 后停止写入、关闭流、抛 `ABORTED`。已写出的部分文件由总入口决定清理策略（见不变量清单 INV-15）。
5. **错误必须带码**（沿用第七章枚举）；归档损坏 → `ARCHIVE_CORRUPTED`。
6. **绝不删除/移动归档文件** ——「解压后删压缩包」是总入口的职责（与压缩侧的删除流程对称）。
7. `overwrite:false` 且目标存在同名 → 抛 `TARGET_EXISTS`，**不覆盖**。

### 3.5 `list(archivePath, options): Promise<ListResult>`

```js
// options
{ signal?: AbortSignal, maxEntries?: number }

// 返回
{
  entries: [
    { name: string,          // 包内相对路径（POSIX，正斜杠）
      size: number,
      compressedSize?: number,
      mtime?: number,
      type: 'file' | 'dir' }
  ],
  truncated: boolean,        // 命中 maxEntries
  count: number
}
```

- 用途：① 校验（与源清单比对）② 前端展示压缩包内容（未来）③ 删除原文件的**精确对应**依据（docs/06 §一：只删真正进包的条目）。
- 只读，不得写盘；`archivePath` 可以被总入口指向 `outputPath` 或 `tempPath`。
- 归档损坏 → 抛 `ARCHIVE_CORRUPTED`。

### 3.6 `test(archivePath, options): Promise<TestResult>`

```js
// options
{ signal?: AbortSignal, deep?: boolean }   // deep=true 时读通全部数据（慢但最可靠）

// 返回
{
  ok: boolean,
  checked: number,                                       // 校验过的条目数
  failures: [ { entry: string, reason: string } ],        // ok=false 时非空
  strategy: 'crc' | 'read-all' | 'external-test'         // 采用的校验策略
}
```

- 用途：**删除原文件的唯一放行条件**（INV-01）。
- 首选 CRC/校验和比对；库不支持时退化为"读通全部条目"（`deep`）。
- **契约要求 `test()` 不抛常规错误**：校验不通过返回 `{ ok:false, failures:[...] }`；只有"文件读不了/格式无法解析"才抛 `ARCHIVE_CORRUPTED`。
- 总入口对两种结果一视同仁：`ok !== true` 或抛错 → **不删原文件**，任务 `failed` + `error.code = VERIFY_FAILED`。

## 四、调用时序（总入口视角）

```
POST /compress/tasks
  └─ preflight：pathGuard → 权限 → 黑名单 → du() → estimate() → 2 倍空间校验   [总入口]
       └─ 分配 outputPath（防覆盖后缀）→ 建任务（落盘）                        [总入口]
            └─ 队列（串行）出队
                 ├─ create(ctx)  → 写 outputPath.part，按 100ms 节流上报进度    [格式包]
                 ├─ rename(outputPath.part → outputPath)                       [总入口]
                 ├─ test(outputPath)                                           [格式包]
                 │    ├─ ok=false → 任务 failed(VERIFY_FAILED)，原文件不动     [总入口]
                 │    └─ ok=true  → 任务 done；若 keepOriginal=false → 进入删除阶段
                 └─ list(outputPath)                                           [格式包]
                      └─ 与"实际进包条目"比对 → 精确删除集合                    [总入口]
```

- 整个链路中，格式包被调用 **≤4 次**（estimate / create / test / list），彼此**不得有隐式共享状态**（同一进程可能串行跑多个任务；格式包必须无实例级可变全局状态，或按 `taskId` 隔离）。
- 总入口负责把 `create()` 的进度写盘 + SSE 广播；格式包**不得直接推 SSE、不得直接写任务文件**。

## 五、注册表契约（总入口侧）

路径：`server/core/compress/registry.js`；注册项来源：`server/plugins/formats/*/index.js`。

| 能力 | 契约 |
|---|---|
| 自动发现 | 启动时扫描 `server/plugins/formats/*/`，逐个 `require/import`；**新增格式 = 加目录**（无需改注册表代码） |
| 双索引 | 同时按 `id` 与**每个扩展名**建索引（`ext` + `extAliases`），对齐参考实现 `format-registry.ts:15-24` |
| 匹配优先级 | ① 精确 `id` → ② 最长复合扩展名（`.tar.gz` 先于 `.gz`）→ ③ 单扩展名 → ④ 遍历问 `canHandle` 的场景由 API 显式给出，不隐式猜 |
| 启动校验 | 校验 `id`/`ext` 唯一性与必需方法齐全；**不合规只禁用该包并告警，不影响其他包**（M4：删/改一个格式不影响其他） |
| 可用性 | 对外 `list()` 返回 `[{ id, ext, mime, name, available, unavailableReason }]`，可用性结果缓存 ≤60s |
| 删除隔离 | 目录不存在 → 该格式从 `/formats` 消失；其余格式照常压缩（M4 关键测试：把 zip 包移走，其余仍能压） |
| 失败暴露 | 注册失败写入启动日志 `storage/logs/`，并在 `/api/v1/health` 的 `formats` 节点体现 |

调用方只需三个方法：`registry.get(id)`、`registry.byExtension(ext)`、`registry.list()`。

## 六、四个格式对号入座

| `id` | 插件目录 | `ext`（别名） | `mime` | 实现库/方式 | 压缩级别 | `available()` 判定 | `estimate` 依据 |
|---|---|---|---|---|---|---|---|
| `zip` | `server/plugins/formats/zip/` | `.zip` | `application/zip` | **archiver**（纯 JS） | 0~9（默认 6） | 依赖可加载即可（纯 JS，无外部依赖） | 扩展名启发式 + `level` 微调 |
| `tar` | `server/plugins/formats/tar/` | `.tar` | `application/x-tar` | **node-tar**（纯 JS，不压缩） | 不适用（`levelRange` 省略） | 依赖可加载即可 | `inputBytes × 1.0` + 每条目 512B 头/填充 |
| `targz` | `server/plugins/formats/targz/` | `.tar.gz`（`.tgz`） | `application/gzip` | **node-tar + 内置 zlib**（`gzip: true`） | 0~9（默认 6） | 依赖可加载即可 | 文本类 ≈0.3，混合 ≈0.6，已压缩格式 ≈0.98 |
| `tarzst` | `server/plugins/formats/tarzst/` | `.tar.zst`（`.tzst`） | `application/zstd` | **node-tar + Node 内置 `node:zlib` 的 zstd**（首选）；回退：外部 `zstd` 命令（路径可用 `ZC_ZSTD_BIN` 指定） | 1~19（默认 3） | **Node ≥ 22.15 的 `zlib.zstdCompress` 可用** **或** 外部 `zstd` 可执行 | 比 gzip 再省 5%~15%（≈0.25~0.55） |

四格式的**共同契约**：都实现第三章全部必需方法；都支持取消与 `signal`；都把产物写入 `tempPath`。

补充约定：

- `tar.zst` 采用「**node-tar 产出 tar 流 → zstd 压缩**」的两段管道（docs/02 选型：`node-tar` 不原生支持 zstd，需拼接管道），因此 `create()` 内部是 `tar.c()` + `zstd` 子进程/编码器的 `pipeline`；取消时必须**同时**终止子进程并清理 `.part`。
- `tar.zst` 的"是否可用"取决于部署环境；**`available()===false` 时 UI 置灰（M4 验收）**，接口返回 `FORMAT_UNAVAILABLE`（API 规范 §八）。
- `zstd` 单文件（无 tar 包裹的 `.zst`）**不在 v1 冻结范围**；将来如要做，新增 `id: "zstd"` / `ext: ".zst"` 的独立包即可，**不改动本文档任何条款**。
- 7z / rar **不在 v1 范围**（docs/02 结论：跨平台成本高），同样按"新增独立包"路径扩展。

## 七、格式包允许抛出的错误码

| code | 何时抛 | 总入口处理 |
|---|---|---|
| `FORMAT_UNAVAILABLE` | `available()===false` 时被调用 `create()` | 任务 `failed`；API 返回 503 |
| `TARGET_EXISTS` | `tempPath`/`outputPath` 已存在 | 任务 `failed`；不覆盖 |
| `ABORTED` | 收到 `signal` 取消 | 清理 `.part`；任务 → `aborted` |
| `DISK_FULL` | 底层 `ENOSPC` | 清理 `.part`；任务 `failed` + `error.code=DISK_FULL` |
| `QUOTA_EXCEEDED` | 底层 `EDQUOT` | 同上（独立码，便于 NAS 配额场景提示） |
| `PERMISSION_DENIED` | `EACCES` / `EPERM` | 任务 `failed` |
| `PATH_NOT_FOUND` | `ENOENT`（源文件在扫描后被删） | 任务 `failed` |
| `ARCHIVE_CORRUPTED` | `list()`/`test()` 无法解析归档 | 任务 `failed`；原文件不删 |
| `VERIFY_FAILED` | `test()` 判定不通过（**建议用返回值而非抛错**） | 任务 `failed`；原文件不删 |
| `INTERNAL_ERROR` | 其他未预期异常（必须带 `details.cause` 摘要） | 任务 `failed`；记录日志 |

错误对象形状（与 API 规范一致）：

```js
{ code: 'FORMAT_UNAVAILABLE', message: 'zstd 不可用：需 Node ≥ 22.15（当前 v22.10.0），也未找到系统 zstd 命令', details: { format: 'tarzst', probe: 'zlib.zstdCompress | which zstd', requiredNode: '22.15.0' } }
```

## 八、边界清单（格式包**不做**的事）

1. ❌ 不做路径白名单校验、不拼接用户输入路径（总入口只给它已校验的原生绝对路径）。
2. ❌ 不做磁盘空间预检、不决定"空间够不够"。
3. ❌ 不做黑名单匹配、不决定"哪些文件跳过"（它只收到"已过滤后的源清单"）。
4. ❌ 不做任务排队/并发控制/重试调度。
5. ❌ 不删除、不移动、不修改源文件（含临时文件以外的任何写操作）。
6. ❌ 不直接写最终产物路径（只写 `tempPath`）。
7. ❌ 不写任务状态文件、不推 SSE、不访问数据库。
8. ❌ 不读全局配置（需要的参数全部由 `ctx.options` 传入）；不自己决定默认压缩级别之外的行为。
9. ❌ 不缓存跨任务的业务状态（进程内可变全局仅允许"可用性探测结果"这类无副作用缓存）。
10. ❌ 不面向 MCP/HTTP 暴露接口（本项目只需进程内 API）。

## 十、与既有文档的出入（显式声明）

| # | 既有文档说法 | 本契约写法 | 性质 | 理由 |
|---|---|---|---|---|
| 1 | docs/03 §二方法表列出 `ext / mime / create / list / test / available / estimate` 七项 | 契约面为上述七项 + `id/name`（元数据）+ 可选 `extAliases/levelRange/defaultLevel/unavailableReason` | 细化 | 注册表需要 `id` 作主键、UI 需要 `name`、复合扩展名需要别名字段；七项语义**未改** |
| 2 | docs/03 写 `create(outputPath, entries, options)`（位置参数） | `create(ctx)` 单对象入参 | 细化 | 参数超过 3 个后位置参数易错；语义（输出路径、条目、选项、进度）完全一一对应 |
| 3 | docs/03 未规定「格式包只写 `.part`」 | 明确 `tempPath = outputPath + '.part'`，总入口负责原子 rename | 新增 | docs/05「重启后绝不能把 .tmp 当正式产物」+ M0 不变量 INV-11 需要落地机制 |
| 4 | docs/03 未规定 `estimate` 的返回形状 | 规定 `{estimatedBytes, ratio, basis, confidence}` | 新增 | 空间预检与抽屉预估都需要机器可读结构；`basis/confidence` 让 UI 能标注"预估" |
| 5 | docs/10 建议参考 `getSupportedExtensions()/getFormatName()/isFormatValid()` 命名 | 本契约采用 `ext/id`（静态属性）与注册表匹配，不引入 `isFormatValid()` | 取舍 | 本项目匹配只发生在"注册表 vs 扩展名"这一处，静态元数据 + 双索引即可；避免每个包再实现一份匹配逻辑（减少分叉） |
| 6 | docs/02 §一提到「zstd 单文件」格式 | v1 只冻结四个格式；`.zst` 单文件列为扩展点 | 范围界定 | docs/11 M4 的四个格式不含 `.zst` 单文件 |
| 7 | docs/12 `plugins/formats/*/` 下同时有 `index.js` 与 `meta.js` | 元数据允许拆到 `meta.js`，但 `index.js` 必须能独立导出完整契约对象 | 细化 | 保持"注册只需一个入口"，拆分仅是内部组织方式 |

严格遵循：docs/03「格式包只负责怎么压」的边界、docs/11 M4 四条验收、docs/02 的库选型与 zstd 风险结论。
