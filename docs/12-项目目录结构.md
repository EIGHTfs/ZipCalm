# 12 项目目录结构

> 定位：各目录的职责与落点规则。
> 本文结构与实际仓库核对（2026-10-24）。

## 一、顶层

```
ZipCalm/
├── server/               后端（Fastify + Node ESM）
├── web/                  前端（Vue 3 + Vite）
├── shared/               前后端共用契约（枚举、版本号）
├── docs/                 设计文档与契约
├── scripts/              启停脚本 + 验收套件 + 工具
├── package.json          依赖与脚本入口
├── config.example.json   配置样例（真实配置在 storage/config.json）
├── LICENSE               MIT
└── README.md
```

**不入库**（`.gitignore`）：`node_modules`（软链到依赖目录）、`web/dist/`、`storage/`（运行态与凭据）、`参考项目/`（第三方源码快照）、`ZipCalm.pid`、`*.log`。

## 二、后端 `server/`

```
server/
├── boot.js              启动入口（配置加载 → 自检 → 监听 → 写 PID → 注册信号）
├── app.js               Fastify 装配（插件、路由、错误处理）
├── config/              配置加载与 schema 校验
├── core/                业务核心（不依赖 HTTP）
│   ├── auth/            认证与会话
│   ├── compress/        压缩编排
│   │   ├── orchestrator.js   预检 → 执行 → 校验 → 删除 的主流程
│   │   ├── preflight.js      磁盘空间预检
│   │   ├── verify.js         压缩包完整性校验
│   │   ├── deleter.js        原文件删除（回收站选路 + 日志）
│   │   ├── blacklist.js      三层黑名单
│   │   ├── registry.js       格式注册表（扫描目录）
│   │   └── sourceWalk.js     源遍历与统计
│   ├── fs/              文件系统能力
│   │   ├── list.js / stat.js      列目录、文件详情
│   │   ├── safePath.js            路径白名单（INV-06）
│   │   ├── writeOps.js            mkdir / rename / move / delete
│   │   ├── roots.js               多存储位置（平台探测 + 容量）
│   │   └── systemTrash.js         群晖系统回收站（synorecycle 封装）
│   ├── hardlink/        硬链接去重
│   │   ├── scanner.js        扫描（size 分组 → 抽样快筛 → 全量哈希）
│   │   └── executor.js       执行（rename → link → unlink）
│   ├── metrics/         指标采集
│   │   ├── collector.js      定时采集 + 环形缓冲 + 事件循环延迟
│   │   └── procfs.js         /proc 解析
│   └── task/            任务系统
│       ├── manager.js        状态机 + 串行队列（activeId）
│       ├── store.js          落盘（tasks.json 原子写+节流 / task-history.jsonl 追加）
│       ├── recovery.js       启动对账
│       └── events.js         事件序列与 SSE 帧
├── http/
│   ├── middleware/      认证、路径守卫（pathGuard）
│   └── routes/          auth · fs · compress · extract · tasks · blacklist · hardlink · metrics · health · formats
├── lib/                 通用（errors · atomic-json）
└── plugins/
    ├── formats/         格式插件（怎么压/怎么解）
    │   ├── _shared/     跨格式共用（条目安全判定、流工具）
    │   ├── zip/  tar/  targz/  tarzst/
    │   ├── rar/         只读解压（extractOnly=true）
    │   └── sevenzip/    7z 双向，双引擎（系统 7z / WASM）
    └── capabilities/    能力插件（在压缩流程里额外做什么）
        └── password/    密码能力，算法在 methods/ 下可追加
```

**分层规则**：`routes/` 只做「参数校验 + 调用 core」；业务逻辑全在 `core/`；`http/` 是入口层，换框架不影响 core。

## 三、前端 `web/`

```
web/
├── index.html
├── vite.config.js
└── src/
    ├── main.js / App.vue
    ├── pages/           FilesPage · TasksPage · MetricsPage · SettingsPage · HardlinkPage · LoginPage
    ├── components/
    │   ├── layout/      TopBar · Sidebar · MainArea · DirectoryTree · BottomTaskBar
    │   ├── compress/    CompressDrawer · ExtractDialog
    │   ├── task/        TaskProgress · TaskDrawer
    │   ├── metrics/     TrendChart
    │   └── common/      ContextMenu · PromptDialog · Icon
    ├── stores/          ui · tasks · metrics · auth（pinia）
    ├── api/             各资源封装（拦截器统一解信封）
    ├── router/          路由表
    ├── utils/           format（字节/时间格式化）· path（面包屑/父路径）
    ├── constants/       枚举（视图模式、轮询间隔等）
    └── styles/          base.css · layout.css
```

**规则**：列表与网格视图都在 `FilesPage` 内（共享选中态与右键/键盘逻辑）；`api/` 是唯一请求出口，便于将来客户端复用错误码语义。

## 四、共享 `shared/`

```
shared/
├── app-version.js     应用版本号（前后端共用一份，避免版本漂移）
├── error-codes.js     错误码枚举（前后端共用）
├── compress-modes.js  压缩模式枚举
├── task-phase.js      任务相位枚举
├── task-status.js     任务状态枚举
└── format-list.js     格式清单
```

**规则**：任何「两端都要知道」的枚举与常量放这里，改一处两端同步 —— 防止"改了这边忘那边"。

## 五、文档 `docs/`

```
docs/
├── 00-需求演进与设计决策.md
├── 01~16               主题设计文档（需求/选型/架构/前端/API/删除/看板/里程碑/目录/工期/约定/硬链接/侧栏）
├── 17-设计与实现差异记录.md
├── M0/                 契约冻结（API 规范 · 插件契约 · 数据模型 · 不变量清单）
├── audit/              对抗式审查结论
└── research/           专项调研（如 MT 插件可行性）
```

**规则**：契约类文档（`M0/`）与代码必须一致，不一致就改文档；设计意图类文档若实现另有选择，登记到 `docs/17`。

## 六、脚本 `scripts/`

```
scripts/
├── start.sh               启停（start / stop / restart / status）
├── setup-dev-deps.sh      依赖安装（自动探测可执行目录）
├── check-drift.js         版本/契约漂移门禁
├── hash-password.js       生成密码哈希（写进 config.json）
├── test-all.sh            一键验收（15 套）
└── test-*.mjs / *.sh      各里程碑验收套件
```

**验收套件**（15 套）：build · m1 不变量 · m2 往返 · m3 任务 · crash 崩溃恢复 · probes 边界探测 · retention 记录清理 · m4 多格式 · m6 黑名单 · m7 指标 · m8fs 文件写操作 · volumes 存储位置 · multiroot 多根 · hlscan 硬链接扫描 · hlexec 硬链接执行。

**为什么测试放 `scripts/` 而不是 `test/`**：这些是**端到端验收脚本**（起服务、走真实 HTTP、造真实文件），不是单元测试。它们与启停脚本同属"运维工具"，放在一起更便于 `test-all.sh` 统一调度。

## 七、运行态 `storage/`（不入库）

```
storage/
├── config.json          运行配置（含密码哈希，绝不入库）
├── tasks.json           活动任务状态
├── task-history.jsonl   任务历史（追加）
├── trash/               项目回收站（非群晖环境 / 测试用）
└── logs/                server.log · start.log · delete-*.jsonl · hardlink-*.jsonl
```

## 八、目录设计的核心逻辑

| 设计 | 目的 |
|---|---|
| `plugins/formats/` 每个格式一个目录 | 插件化，删/改/加格式互不影响 |
| `core/` 按能力分（task / compress / fs / hardlink / metrics / auth） | 业务集中，路由只做参数校验与调用 |
| `http/` 独立 | HTTP 只是入口层，换框架不影响 core |
| `components/` 按功能分组 | 文件、压缩、任务、监控各自成套，不混 |
| `api/` 是唯一请求出口 | 便于将来客户端复用错误码语义 |
| `shared/` 放两端共用枚举 | 防止"改了这边忘那边" |
| `docs/` 契约与设计分离 | 契约必须与代码一致；设计意图的偏离单独登记 |
| 验收脚本集中在 `scripts/` | 与启停脚本同属运维工具，便于统一调度 |

## 九、给将来客户端留的口子

目录里**没有为 APK 单独建目录**（现在还不存在，避免空目录）。但已铺好几处：

- `server/http/routes/` 全是纯 API，无服务端渲染 → 客户端直接调
- `shared/` 的枚举两端共用 → 客户端抄同一份
- `web/src/api/` 是请求封装样板 → 客户端可照此写
- `server/http/middleware/auth.js` 支持 Bearer Token → 客户端直接用

等 APK 真正开始时，再建 `android/` 与 `web/` 平级。

## 十、一句话总结

**顶层三块：`server/`（业务）、`web/`（前端）、`shared/`（契约）。** 后端核心是 `plugins/formats/`（插件化）+ `core/task/`（任务系统）+ `core/compress/`（业务编排）；前端核心是 `pages/` + `components/` + `stores/` + `api/` 四层。`shared/` 是两端一致性的保险，`docs/` 是契约不漂移的保险，`scripts/test-*` 是行为不回归的保险。
